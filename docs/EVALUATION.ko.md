# 평가 프로토콜

_[English](EVALUATION.md) · 영문 문서가 기준입니다._

아직 공개한 정확도나 성능 결과가 없습니다. 이 문서는 앞으로의 결과가 따라야 할
측정 방식을 미리 정해, 목표치가 달성한 수치처럼 제시되는 일을 막습니다.

## 버전이 붙는 평가 단위

모든 결과는 다음을 함께 기록해야 합니다.

- 데이터셋과 변형 집합의 버전
- 해당하는 경우 계약, 규칙, 프롬프트, 모델, 엔진의 버전
- 정확한 명령과 커밋 SHA
- 실행 환경
- 표본 수와 집계 방식
- 알려진 한계와 판단 보류

## 계획된 측정

| 영역             | 정의                                                        |
| ---------------- | ----------------------------------------------------------- |
| 항목 연결 정확도 | 커밋된 정답 연결과의 항목 단위 일치                         |
| 모호성 처리      | 잘못된 자동 승인 비율과 `REVIEW_REQUIRED` 비율              |
| 재현 결정성      | 동일한 입력을 반복했을 때의 정본 해시 일치                  |
| 변형 내성        | 순서 섞기, 중복, 시각 표기, 지연 도착 변형 이후의 결과 일치 |
| 시나리오 결과    | 합성 시나리오의 예상 결과와의 일치                          |
| 증거 완전성      | 발견의 이벤트 참조가 원본 행 해시까지 이어지는 비율         |
| 조사 소요        | 문서화된 비교 절차 아래에서의 완료 시간                     |
| 성능             | 이벤트 수에 따른 실행 시간과 최대 메모리                    |

## 기반 점검

현재 단위 시험이 확인하는 것은 다음의 엔지니어링 불변식뿐입니다.

```bash
pnpm test
```

- **공개 시세의 파생과 정규화** — 응답에서 파생한 JSONL과 생성된 행을 그대로
  재현하고, 일별 기반·데이터셋 해시를 고정하며, 반복·순서 섞기·파생 중복에도
  그 값을 유지하고, 명시적으로 신뢰할 수 없는 거래 주체 요청은 사례 승인이나
  평가 전에 거부합니다. 커밋된 표본은 2026-09-03 금융위원회 코스피 시세 943건
  가운데 처음 40건입니다. 예상 규칙 결과가 없으며 탐지 성능 기준이 아닙니다.
  정확한 출처, 이용 허락 범위, 해시와 한계는
  [소스 README](../packages/published-data/src/sources/real/README.md)(영문)에
  기록되어 있습니다.
- **행 순서 불변성** — 커밋된 네 이벤트 기반 픽스처의 모든 순열이 정본 순서와
  결과 해시를 그대로 유지합니다. 파싱된 원본 행의 대표적인 순열도 두 형식과 세
  규칙 사례 모두에서 승인된 HTTP 경계를 통과하며, 규칙 평가와 원본 추적이
  달라지지 않습니다. 이 점검에서 원본 파일의 바이트와 좌표는 고정입니다.
- **고정된 정답 해시** — 커밋된 픽스처 하나를 정본 결과 해시 문자열에
  고정합니다.
- **완전 중복 허용** — 원본 식별자가 같은 완전한 중복은 정본 이벤트를 바꾸지
  않고 합쳐집니다.
- **식별자 충돌 거부** — 이벤트나 원본 식별자가 상충하게 재사용되면 입력 순서와
  무관하게 실패합니다.
- **시각 표기 동치** — 오프셋 표기와 `Z` 표기가 같은 순간으로 정규화되며, UTC
  날짜 경계를 넘는 경우도 포함합니다.
- **밀리초 미만 순서** — 지원하는 정밀도는 순서를 유지하고, 나노초보다 세밀한
  시각은 거부합니다.
- **로케일 독립 순서** — 정본 키는 로케일 자료 없이 UTF-16 코드 단위 순서를
  씁니다.
- **휘발성 메타데이터 제외** — 수집 메타데이터는 분류되어 정본 결과 해시에서
  제외됩니다.
- **혼재된 시퀀스 정책** — 시퀀스가 섞여 존재하면 닫힌 상태로 실패하고, 전부
  없는 경우에는 이벤트 ID로 정렬합니다.
- **형식 수렴** — 동등한 커밋 소스 형식들은 하나의 정본 데이터셋과 결과 해시로
  수렴합니다.
- **소수 표기 수렴** — 허용되는 끝자리 0과 부호 있는 0의 표기는 중복 분류와
  해싱 전에 정규화되고, 원본 행 해시는 원래 문자열을 대상으로 하므로 서로 다르게
  유지됩니다.
- **데이터셋 프로파일 결정성** — 프로파일은 이벤트 순서를 섞어도, 커밋된 소스
  형식이 달라도 동일합니다.
- **항목 연결 승인 결속** — 승인은 검증된 제안과 실제 실행된 변환에 묶입니다.
- **기록 집합 완전성** — 선언된 행이 빠지거나 승인된 열이 없으면 결과 해싱 전에
  실패합니다.
- **공유되는 승인 직렬화** — 브라우저 승인과 재현 검증이 RFC 8785 유한 수 규칙을
  포함해 같은 정본 바이트를 쓰고, 브라우저 해싱이 실패하면 재현은 막힌 채로
  남습니다.
- **항목 연결 일치 보고** — 엔진이 연결된 정본 이벤트에 대한 항목별 일치와, 각
  연결 적용의 검토 결과를 보고합니다.
- **도달 가능한 연결 검토** — 형식 B는 `source_note`를 검토 대상으로 제시하고,
  사유가 적힌 재정의가 없으면 재현이 실패하며 있으면 성공합니다. 형식 A는 끝까지
  해석됩니다.
- **시나리오 분류** — 완전한 증거 사례는 선언된 판단 기준을 모두 충족해
  `SUPPORTED`에 고정됩니다. 참여자 분산 사례는 평가할 증거는 충분하지만 집중도
  기준을 충족하지 못해 `NOT_SUPPORTED`에 고정됩니다. 매수·매도 구분이 빠진 사례는
  구간 내 체결 네 건을 모두 비교 불가로 제외하고
  `INSUFFICIENT_ELIGIBLE_EVENTS` 사유의 `INCONCLUSIVE`에 고정됩니다. 같은 시험이
  의미상의 결과 해시, 선언된 순서, 중복 허용, 발견 참조, 데이터셋 해시 독립성도
  함께 고정합니다.
- **커밋된 충돌 검토** — 공개 스키마 기반 합성 FIX 원본에서 하나의 `ExecID(17)`가
  서로 다른 `TransactTime(60)`과 `LastPx(31)` 값으로 재사용됩니다. 이 사례는
  `CONFLICTING_SOURCE_IDENTITY` 사유의 `INPUT_REVIEW_REQUIRED`에 고정되며, 규칙
  결과와 정본 결과 해시는 생성되지 않습니다.

시나리오 분류의 표본은 직접 작성한 합성 픽스처 세 개이고, 별도의 충돌 입력
픽스처가 재현 전 검토 경로를 고정합니다. Node 22.18.0, pnpm 10.33.2,
Vitest 4.1.11, Linux WSL2 x86_64에서
`pnpm test -- packages/replay-engine/src/rapid-price-lift-golden.test.ts packages/replay-engine/src/published-execution-schema.test.ts`로
실행합니다. 이 결과는 선언된 사례와 사례마다 예시로 정한 기준값만 검증하며,
독립된 자료나 실제 시장 자료에서의 성능을 추정하지 않습니다.

이 점검들은 항목 연결 정확도, 이상탐지 품질, 실제 시장으로의 일반화, 사용자
생산성, 대규모 성능을 측정하지 않습니다.

공개 시세 점검은 Node 22.18.0, pnpm 10.33.2, Vitest 4.1.11, Linux WSL2
x86_64에서 오프라인으로 실행합니다.

```bash
pnpm exec vitest run packages/replay-engine/src/real-market-data.test.ts apps/web/src/app/api/replay/real-market-data-route.test.ts
```

잘못된 날짜, 파서 경계 사례, 일별 종류의 규칙 적격성은 전부 합성 표본으로
확인합니다. 그 시험을 만들기 위해 실제 원본 값을 고치는 일은 없습니다. 거부되는
거래 주체 사례는 신뢰할 수 없는 부정 요청으로만 존재하며, 원본의 사실도, 등록된
시나리오도, 공개된 가설도 아닙니다.

## 공개 기준

어떤 수치가 대표 README에 실리려면 그 평가 사례와 원자료 또는 기계가 읽을 수
있는 요약이 커밋되어 있어야 하고, 명령이 재현 가능해야 하며, 한계가 그 수치
옆에 링크되어 있어야 합니다.
