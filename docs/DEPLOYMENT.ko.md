# 배포: 환경과 일일 예산

[English](DEPLOYMENT.md) · 영문 문서가 기준입니다. 이 문서는 환경 설정과
일일 모델 예산을 다룹니다. 릴리스 승격, 배포 검증과 롤백 절차는 영문
문서를 따릅니다.

## 환경

로컬·CI·Preview·Production은 기본적으로 픽스처 모드입니다. 페이지 준비나
빌드는 모델을 호출하지 않습니다. 자격 증명이 있다는 이유만으로 실제
모델 호출을 켜지 않습니다. 배포된 모델이나 저장소 설정을 이번 변경에서
검증하거나 추가하지 않았습니다.

명시적인 실제 제공자 설정은 서버 전용 `AI_MODE=ai`와
`AI_PROVIDER_BASE_URL`, `AI_PROVIDER_API_KEY`, `AI_PROVIDER_MODEL`을
모두 요구합니다. URL은 API 경로를 포함하는 HTTPS 주소여야 하고 사용자
정보·쿼리·프래그먼트는 금지됩니다. 고정된 모델 ID를 쓰세요. 요청과 응답,
원시 추적과 자격 증명은 브라우저에 공개하지 않습니다. 제공자는 항목
연결만 제안하며 승인하거나 원본 행·재현 규칙·결과를 바꾸지 못합니다.

## 공개 모델의 일일 예산

공개 실제 모델 요청은 같은 예산을 사용하는 Vercel 함수들이 공유하는
Upstash Redis를 요구합니다. 내장 `fetch`로
[REST 명령 API](https://upstash.com/docs/redis/features/restapi)를 사용하며
추가 의존성은 없습니다. 단일 `EVAL`이 주 노드에서 두 카운터를 함께
확인하고 예약합니다. 캐시된 별도 읽기나 인스턴스 메모리를 쓰지 않습니다.
전용 데이터베이스를 쓰고 카운터 자동 퇴출을 금지하세요. 삭제·퇴출은
한도를 초기화합니다. 같은 예산을 쓰는 모든 함수·배포는 같은 저장소,
한도와 비밀키를 사용해야 합니다. Preview 실험은 별도 저장소와 제공자
예산으로 분리하세요.

| 변수                        | 의미                                                            |
| --------------------------- | --------------------------------------------------------------- |
| `UPSTASH_REDIS_REST_URL`    | 경로·사용자 정보·쿼리·프래그먼트가 없는 Redis REST HTTPS 오리진 |
| `UPSTASH_REDIS_REST_TOKEN`  | 데이터베이스 쓰기 권한을 가진 서버 전용 비밀키                  |
| `AI_LIMIT_VISITOR_SECRET`   | 함수들이 공유하는 최소 32바이트의 무작위 HMAC 비밀키            |
| `AI_LIMIT_VISITOR_REQUESTS` | KST 일일 방문자 요청 수, 미설정 시 15                           |
| `AI_LIMIT_GLOBAL_CALLS`     | 필수 KST 일일 전체 모델 호출 한도, 무제한이나 기본값 없음       |

한도는 1부터 1,000,000,000까지의 양의 정수입니다. 변수는 모두 서버
전용이며 `NEXT_PUBLIC_` 이름을 만들거나 로그·브라우저에 공개하지 마세요.
픽스처 배포에서는 미설정으로 둡니다. 실제 배포에서 켜는 것은 운영자의
명시적인 환경 선택이며 코드 검토만으로 계정이나 Redis를 만들지 않습니다.

플랫폼 `VERCEL=1`과
[`x-vercel-forwarded-for`](https://vercel.com/docs/headers/request-headers#x-vercel-forwarded-for)의
유효한 단일 IP만 신뢰합니다. 쿠키, 요청 본문의 신원,
`x-forwarded-for` 대체값이나 Vercel 밖의 헤더는 신뢰하지 않습니다.
우회하려고 `VERCEL=1`을 직접 설정하지 마세요. Vercel 앞에 프록시가
있으면 방문자들이 프록시 IP 한도로 묶일 수 있습니다. 다른 호스팅은
별도로 검토한 신뢰 가능한 신원 어댑터가 필요합니다.

Redis에는 플랫폼 IP와 KST 날짜를 서버 비밀키로 HMAC-SHA-256 처리한
방문자 키, 방문자 요청 횟수, 전체 예약 호출 횟수만 저장합니다. 앱은 원시
IP를 저장하거나 로그에 남기지 않습니다. 키와 횟수는 다음 00:00 KST에
만료되어 최대 24시간만 남으며 HMAC은 매일 바뀝니다. 이 카운터는 개인
신원이 아니고 같은 IP의 사람들은 한도를 공유합니다. 비밀키는 KST 자정에
교체하세요. 도중 교체하면 방문자 한도가 초기화되지만 전체 한도는 계속
적용됩니다. 키·본문 로그나 해당 KST 날짜 이후 카운터 백업을 금지하세요.
앱의 만료 처리는 제공자의 로그·백업 삭제를 검증하지 않습니다.
[데이터 처리](DATA_HANDLING.ko.md)를 참고하세요.

직접 제안은 방문자 요청 한 번과 전체 호출 한 번을 예약합니다.
공통 `runPublicModelRequest`는 향후 라우팅을 위해 방문자 한 번과 전체
호출 두 번도 예약하며 세 번째 또는 만료된 호출을 차단합니다. 라우팅과
변형 데모는 아직 계획이며 구현 시 이 경계를 사용해야 합니다. 실패하거나
쓰지 않은 예약은 환불하지 않습니다. 전송 실패 뒤 비용 발생 여부를 알 수
없기 때문입니다. 이 보수적 한도는 호출 시도를 제한하며 토큰·금액 상한은
아닙니다. 제공자 재시도는 없습니다.

한도 초과, 설정 누락, 플랫폼 IP 부재, 저장소 장애·시간 초과 시 모델
호출 없이 고정 설명과 HTTP 422 `REVIEW_REQUIRED`를 반환합니다.
브라우저는 검토 응답 계약을 검증한 뒤 사유를 표시합니다. 항목 연결 경로는
`application/json`을 요구하며 charset은 허용합니다. Origin 헤더가 요청
URL의 출처와 다르면 본문 파싱·예산 예약 전에 거부합니다. Origin 없는
JSON 클라이언트는 허용하지만 타 출처 브라우저의 JSON 요청은 사전 요청이
필요하고 이 경로는 CORS 접근을 허용하지 않습니다. 단순 텍스트·폼 요청은
방문자 예산을 소비하지 못합니다.
저장소 시간 제한은 응답 본문을 포함해 3초입니다. Redis는 저장소 시계로
예약 날짜를 확인하고 서버도 자정을 지나 도착한 허용 응답을 거부합니다.
자정 전에 시작한 호출은 자정 뒤 끝날 수 있지만 추가 호출은 새 날짜의
예약을 요구합니다. 픽스처, 페이지 준비·빌드, 기존 암호화 영수증 재현은
카운터나 모델을 호출하지 않습니다.

일반 `pnpm dev` 요청은 신뢰할 플랫폼 신원을 얻을 수 없으므로 실제
호출이 차단됩니다. 로컬 제공자 확인은 아래 수동 평가 명령을 사용하세요.
테스트는 공유 메모리 가짜 저장소와 모의 Redis 전송을 사용하며 호스팅
Redis나 실제 Vercel 설정을 검증하지 않았습니다.
[ADR 0063](adr/0063-reserve-public-model-budgets-in-shared-daily-counters.md)(영문)을 참고하세요.

## 수동 로컬 평가

`pnpm eval:models --live --scenario concentrated-buy-dialect-a.csv`는
`AI_EVALUATION_MODELS`의 명시적인 모델 목록과 각 비밀키를 요구하며
CI에서 실행을 거부합니다. 서버 어댑터를 직접 호출해 공개 웹 제한기를
우회하므로 평가 예산은 별도로 관리합니다. 로컬 기록은 무시되는
`dist/mapping-runs/`에 남으며 원시 응답이나 자격 증명은 보존하지 않습니다.
기본 `pnpm eval`과 검증은 오프라인 픽스처 실행입니다. 실제 모델 품질이나
호스팅 연동을 측정했다는 의미는 아닙니다.
