# 일별 시세 정규화

_[English](DAILY_QUOTES.md) · 영문 문서가 기준입니다._

직접 조작 모드에는 금융위원회가 공개한 `basDt=20260903` 코스피 일별 시세가
들어 있습니다. 943건 가운데 첫 페이지 40건입니다.
`real/fsc-stock-quotes-20260903.jsonl`을 고르고, 원래 열과 출처 기록을
확인하고, 날짜·종가·거래량 해석에 사유를 적고, 그 항목 연결을 그대로 승인한 뒤
**원본 정규화**를 누릅니다. 정규화는 사례 승인이나 패턴 판정 없이 완료됩니다.
따라가기의 사례는 여전히 합성 자료이고, 공개 자료를 쓰는 교차시장 규칙은 별도의
엔진 수준 정답 기록으로 다룹니다.

## 계약의 공존

| 입력           | 기존 분기                                                  | 일별 정규화 분기                                                      | 평가까지 가능한 일별 분기                                                 |
| -------------- | ---------------------------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Trade Event    | `schemaVersion: 1.1`, `ORDER_NEW`, `ORDER_CANCEL`, `TRADE` | `schemaVersion: 1.2`, `DAILY_QUOTE`만                                 | `schemaVersion: 1.3`, `DAILY_QUOTE`에 거래일·OHLC·전일 대비 변화 추가     |
| 항목 연결 제안 | `mappingVersion: 1.4`, 이벤트 스키마 `1.1` 상수            | `mappingVersion: 1.5`/`1.6`, 이벤트 스키마 `1.2`와 필수 `DAILY_QUOTE` | `mappingVersion: 1.7`, 이벤트 스키마 `1.3`과 직접 또는 합성 원본 식별자   |
| 변환           | 기존 변환                                                  | `eventTime`에만 쓰는 `YYYYMMDD_TO_KST_DAY_START_ISO` 추가             | 발행처의 소수점 앞 0 생략을 다루는 검토된 `PUBLISHER_DECIMAL_STRING` 추가 |

공개된 지수 관측값은 정규화만 하는 출력에 항목 연결 제안 `1.6`을 씁니다. 평가까지
가능한 코스피 200 기준선 등록은 이벤트 `1.3`과 제안 `1.7`을 쓰며, 같은 순서의
`compositeSourceEventId`를 그대로 유지합니다. 금융위원회의 자연 키
`(basDt, idxNm)`는 승인된 정규화 과정에서만 예약된 NUL 구분자로 결합되며, 원본
열도 커밋된 아티팩트도 다시 쓰이지 않습니다. 구성 요소가 없거나 NUL을 포함하면
닫힌 상태로 실패합니다. 기존 `1.4`, `1.5`, `1.6` 제안은 이전이 필요 없습니다.
평가까지 가능한 선물 등록은 직접적인 `srtnCd` 식별자를 `1.7`로 연결하고, 위클리
옵션은 `1.5`에 남습니다.

사례 재현 화면은 커밋된 완전한 소스를 계약 상한인 1,000행까지 한 요청으로
받습니다. 덕분에 546행짜리 위클리 옵션 시계열을 잘라내지 않고도 요청 크기의
상한을 유지할 수 있습니다.

모든 객체 분기는 여전히 엄격합니다. 기존 페이로드는 이전이 필요 없고, 새로운
종류와 변환은 이전 제안에 들어갈 수 없습니다. 일별 종류는 아티팩트의 상수이며
제안 승인 해시에 포함됩니다. 같은 목표로 향하는 항목 연결이 하나 더 있으면 행에
적용되기 전에 `DUPLICATE_TARGET_FIELD`로 거부됩니다.

날짜 변환은 0001–9999년의 유효한 그레고리력 날짜를 나타내는 ASCII 숫자 여덟
자리만 받습니다. 지역 시간대 해석이나 날짜 넘김 없이
`YYYY-MM-DDT00:00:00+09:00`을 돌려줍니다. 이것은 검토자가 승인한 거래일
기준점이며, 관측된 체결 시각도, 장 개시 시각도, 발행처가 돌려준 오프셋도
아닙니다. 기존 정본화 과정이 이를 UTC 나노초 표현으로 바꿉니다. 기존 소수 문자열
정규화는 그대로입니다. 제안 `1.7`은 소수점 앞에 빠진 0만 정본화하는, 발행처
전용의 검토된 변환을 추가합니다. 원본 문자열은 보존됩니다.

이벤트 스키마 `1.2`와 `1.3`은 일별 전용입니다. 이벤트 `1.3`은 원본의
`tradingDate`, OHLC, 절댓값 `netChange`를 요구하며, 모두 정본 투영으로
보호됩니다. 기존 선택 항목들은 계약상의 정의를 그대로 유지하지만, 거래 주체가
없는 공개 시세는 `side`, `actorId`, `counterpartyId`, `orderId`, `sequence`,
`receivedAt`을 비워 두어야 합니다. `EVENT_TYPE_CODE` 변환은 여전히 원래의
체결·주문 코드만 받습니다.

픽스처 공급자 레지스트리는 이제 아티팩트 해시별로 제안 버전과 상수를
가집니다. 일별 입력 상수는 등록된 아티팩트와 일치해야 합니다. 알 수 없는 이전
아티팩트는 여전히 해석되지 않은 항목 연결 제안을 내놓습니다. 등록되지 않은 일별
아티팩트는 거부됩니다. 공급자 모드는 `fixture`로 유지됩니다.

## 공개된 항목의 해석

등록된 항목 연결은 허용된 응답의 15개 열을 모두 설명합니다. 아래 다섯 개가
연결되고, 나머지 열 개는 항목별 근거와 완전한 원래 값을 유지한 채 명시적으로
연결하지 않은 것으로 남습니다.

| 발행처 항목 | 정본 목표       | 변환과 해석                                              |
| ----------- | --------------- | -------------------------------------------------------- |
| `srtnCd`    | `sourceEventId` | `IDENTITY`. 허용된 하루 안에서의 종목 키                 |
| `isinCd`    | `instrumentId`  | `IDENTITY`. 종목 식별자                                  |
| `basDt`     | `eventTime`     | `YYYYMMDD_TO_KST_DAY_START_ISO`. 선언된 하루 시작 기준점 |
| `clpr`      | `price`         | `DECIMAL_STRING`. 일별 종가                              |
| `trqu`      | `quantity`      | `DECIMAL_STRING`. 일별 누적 거래량                       |

날짜, 종가, 거래량은 `REVIEW_REQUIRED`와 픽스처 확신도 `0`, 그리고
`fields.<index>`에 빈칸이 아닌 항목별 승인 사유를 요구합니다. 이 점수는 검토
신호이지 측정된 모델 확신도가 아닙니다. 그 밖에 돌아온 열은, 일부러 연결하지
않은 열까지 포함해, 손상 없이 그리고 명시적으로 설명되어 있어야 합니다. 종가에
누적 거래량을 곱한 값이 발행처가 말하는 거래대금이라고 주장하지 않습니다.

## 진행 경계

사유가 적힌 재정의를 포함한 정확한 항목 연결 승인이 있고 매니페스트가 없으면
원본이 정규화됩니다. 기존 HTTP 응답은 `200 MAPPING_APPROVED`이며, 정본 개수,
정렬된 이벤트 ID, 기반 `canonicalResultHash`를 담습니다. 평가, 발견,
프로파일, 전체 이벤트, 원본 추적은 담지 않습니다.

거래 주체가 없는 데이터셋은 `actorIds: []`를 가집니다. 스키마가 유효하고 승인이
제대로 묶여 있어도 거래 주체가 비어 있지 않은 사례는 HTTP 422와
`CASE_REVIEW_REQUIRED`, 그리고
`["caseManifest", "hypothesis", "actorIds", i]` 위치의
`ACTOR_OUTSIDE_DATASET_PROFILE`로 거부됩니다. 평가기는 호출되지 않고, 재현도
결과 해시도 돌려주지 않습니다. 거래 주체가 빈 값이면 요청 검증에서 실패하며,
잘못된 사례 승인은 프로파일 오류보다 우선합니다. 매니페스트 없는 일반 요청이
`CASE_REVIEW_REQUIRED`에 도달했다고 말하지 않습니다.

일별 제안에서 화면의 동작은 "원본 정규화"입니다. 한계 안내와 직접 조작 모드
설명은 매니페스트가 없을 때 항목 연결 승인만 요구합니다. 결과가 비어 있으면
정규화를 안내하고, 사례 반복 조작은 사례 매니페스트가 있는 소스에만
나타납니다. 한계 안내는 앞으로 사례를 만들려면 시각·매매 방향·거래 주체·가격·
수량을 갖춘 실제로 허용 가능한 체결과 별도의 사례 승인이 필요하다고
설명합니다. 거래 주체만 덧붙인다고 일별 시세가 체결 자료가 되지 않습니다.

## 증거와 재현

화면에 표시되는 출처 기록은 `basDt`로 공개된 하루를 나타냅니다. 여러 거래일에
걸친 전체 시계열은 대신 `basDtRange`와 그 안의 `begin`, `endInclusive`를 쓰며,
구간 기록을 단일 날짜 항목에 실어서는 안 됩니다. 기존 단일 날짜 출처 기록은
이전이 필요 없고, 이미 있는 구간 문자열은 두 끝점으로 나누어야 합니다.

이 아티팩트는 `bounded-window` 취득 범위를 씁니다. 옆에 있는
`.acquisition.json`은 이미 기록된 첫 페이지 정책을 분류할 뿐, 과거의 출처
기록이나 원본 해시를 바꾸지 않습니다. 별도의
[전체 시계열 방식](PUBLISHED_ACQUISITION.md)(영문)은 이 구간을 넓히지도, 다른
실제 아티팩트를 취득하지도 않습니다.

[옆에 있는 출처 기록과 재현 절차](../packages/published-data/src/sources/real/README.md)(영문)에
응답, 이용 허락 범위, 정확한 요청, 모든 아티팩트 해시가 기록되어 있습니다.
취득 시각은 `2026-09-05T19:31:27.527Z`(한국시간 2026-09-06)이고, 제한 없는 이용
허락은 같은 UTC 날짜에 확인했습니다. `2026-09-05T19:36:42.695Z`에 한 번 다시
받아 온 결과는 원본 바이트와 항목 값이 동일했습니다. 앞으로 발행처가 정정하면
달라질 수 있습니다.

실제 아티팩트 시험이 JSONL과 생성된 행을 재현하고 기반·데이터셋·항목 연결 승인
해시를 고정합니다. 실행 명령은 다음과 같습니다.

```bash
pnpm exec vitest run packages/replay-engine/src/real-market-data.test.ts apps/web/src/app/api/replay/real-market-data-route.test.ts
```

Node 22.18.0, pnpm 10.33.2, Linux WSL2 x86_64에서 확인한 결과, 정규화는 40개의
정본 이벤트와 기반 해시
`f8bb2a21d695aab89e826039861204ecb741d5f56ecab69e354c9b5840ae25fc`를
돌려줍니다. 이는 고정된 이 구간에 대한 결정론적 정규화를 보인 것이지, 규칙
성능 기준이나 실제 시장 탐지 정확도에 대한 주장이 아닙니다. 잘못된 날짜, 파서
경계 사례, 식별자 충돌, 규칙 비적격은 전부 합성 표본으로 확인합니다. 실제 자료
경로의 부정 시험은 거부되는 요청 안에서만 신뢰할 수 없는 거래 주체 주장을
제공하며, 그 사례를 평가하지 않습니다.

원래의 주식 시세 구간은 엔진 `0.7.0-canonical-decimal`에 남아 있고 여전히 사례
매니페스트도, 규칙 결과도, 패턴 판정도 없습니다. 완전한 코스피 200 기준선과
최근월 선물 등록은 이벤트 `1.3`을 쓰며, 별도의
`0.8.0-cross-market-session-reversal` 엔진 진입점이 두 자료의 정본 이벤트를
합쳐 승인된, 거래 주체가 없는 사례 매니페스트 `1.4`를 평가합니다.
[ADR 0022](adr/0022-normalize-daily-quotes-with-version-coexistence.md)(영문),
[ADR 0032](adr/0032-evaluate-declared-cross-market-session-reversals.md)(영문)를
참고하세요.
