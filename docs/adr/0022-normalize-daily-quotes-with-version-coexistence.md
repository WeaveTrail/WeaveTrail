# ADR 0022: Normalize daily quotes with version coexistence

## Status

Accepted. Verified with the committed FSC KOSPI daily quotation artifact for
2026-09-03 and its deterministic derivation tests.

## Context

Daily quotation records have a trading date, closing price and aggregate volume.
Interpreting them as individual executions would attach timing and behavior the
source does not supply. Existing mapping proposals require a per-row event kind
and an explicit timestamp; inventing a source column would hide that difference.
A global input-version migration would also alter protected canonical fields
and invalidate existing golden hashes without changing their meaning.

## Decision

Keep strict Trade Event `1.1` and Mapping Proposal `1.4` branches unchanged.
Add a daily-only Event `1.2` and Proposal `1.5` branch. Its artifact constants
include `eventType: DAILY_QUOTE` and are protected by full-proposal approval.
Count that constant as the required event kind and reject a competing field
target before applying rows. Do not expand `EVENT_TYPE_CODE` or introduce a
generic constants system.

Declare one date transform, `YYYYMMDD_TO_KST_DAY_START_ISO`, applicable only to
daily `eventTime`. Validate the Gregorian date explicitly, then emit the declared
Korean day-start anchor with `+09:00`. This is an interpretation requiring review;
it is not execution time or an offset returned by the publisher. Closing price
and aggregate volume likewise require justified overrides. Missing participant
and execution attributes remain absent.

Preserve the existing canonical projection, UTC normalization, decimal-string
arithmetic, event ordering and duplicate handling. Keep the engine version
`0.7.0-canonical-decimal` because these algorithms and the meaning of legacy
inputs have not changed. New input versions distinguish new daily semantics.
Keep Case Manifest `1.3`, approval records, rule versions and HTTP shapes.
SourceTrace retains its existing execution-event contract: a daily actorless
source cannot produce case findings or a source trace.

Package a verified response offline: retain its entity-body bytes, extract every
complete string-valued item in returned order, emit compact JSON per line with
one final LF, and generate coordinates using the JSONL hash and physical line.
Reproduce generated row bytes from the same response. Envelope extraction is
packaging; runtime ingestion continues to use the existing hash-checked JSONL
parser. Refuse nonstring item values rather than coercing financial numbers.
The scenarios package continues to depend on contracts, not replay-engine.

## Consequences

Existing artifact bytes, proposals, approvals, manifests and goldens require no
migration. Synthetic daily tests add a separate captured foundation golden and
prove repeat/shuffle/derived-duplicate invariance. Display provenance is outside
the protected artifacts and canonical hashes.

Mapping approval can normalize an actorless daily artifact without proposing a
case. A submitted case cannot pass actor membership validation, so evaluation
never runs. Normalization produces a foundation hash, not a pattern verdict.
The working surface exposes this limitation while keeping normalization enabled.

The acquisition prerequisites remain separate from algorithm tests. The accepted
response and adjacent provenance establish this artifact's origin, permission and
window; actual-artifact tests verify all generated bytes and the manifest-free
normalization boundary. This source is not a labeled rule benchmark.
