# 공개 데이터 반입 검토

영문 문서가 기준입니다. [English](PUBLISHED_DATA_ADMISSION.md)

검토일: **2026-09-29 UTC**.
[지원 범위 확대](https://github.com/WeaveTrail/WeaveTrail/issues/225)를 위해
공식 출처의 이용 조건을 확인했습니다. 이번 검토로 새 시세, 종목 목록,
만기 일정 또는 계약 명세를 수집하거나 반입하지 않았습니다.
[커버리지 매니페스트](COVERAGE.ko.md)는 기존 5개 수집 기록에서만 파생됩니다.
전체 상장주식과 더 긴 주요 지수 기간을 커밋된 검증 계층에 반입하는 작업은
이용 허가 조건 때문에 미완료입니다.

### 이번 반입 검토의 범위

주식·지수 페이지는 자료를 공공누리 4유형으로 표시하고, 허가 없는 제3자
제공과 재배포를 명시적으로 금지합니다. 이번 검토는 원본 응답과 파생 파일을
공개 저장소에 반입할 수 있는지만 판단합니다. 비공개 서버 이용이나 제한된
결과 표시에 관한 조건은 별도로 검토해야 하며, 여기서는 결론을 내리지
않습니다. 적용 가능한 허가 없이 원본이나 원본이 포함된 파일을 GitHub,
이용자 다운로드 또는 외부 내보내기로 제공하지 않습니다.

현재 서비스 저장소 계약도 검토된 재배포 권한을 요구합니다. 이는 프로젝트의
반입 규칙이며, 출처가 비공개 보관을 금지한다는 판단은 아닙니다. 내부 전용
저장 경로에는 별도의 계약과 외부 내보내기 경계가 필요합니다. 이번 검토는
그 경로를 구현하지 않았고, 별도 종목 목록·파생상품·투자자 집계 데이터도
다루지 않습니다. 새 데이터셋은 반입하지 않았고 커버리지 평가도 동일합니다.

주식·지수 페이지의 수정일은 2026-09-07, 종목 목록 페이지는 2026-09-23입니다.
페이지 수정일은 특정 조건의 변경 시점을 증명하지 않습니다. 기존 수집 당시의
허가·조회 기록은 그대로 보존하며, 이번 검토는 후속 조건의 소급 적용 여부를
판단하지 않습니다. 이전 기록이 새 수집을 허가하지도 않습니다.

저장소 반입을 재개하려면 원본 바이트 보존, 저장소 커밋, 결정적 변경, 제3자 재배포를 명시적으로
허용하는 검토된 허가와 출처·확인 시각·표시 조건이 필요합니다. 유료 API 접근이나
자동 활용 승인만으로 이 권리가 확보되지 않습니다.
[서비스 스냅샷](SERVICE_SNAPSHOTS.md)(영문)의 현재 계약도 재배포 권한을
요구합니다. 계약을 바꾸지 않고 데이터를 옮기는 것만으로 반입 규칙을
우회할 수 없습니다.
후보 데이터의 크기는 **미측정**입니다. 허가 확인 단계에서 수집을 중단했으며,
추정치로 크기 초과 여부를 판단하지 않았습니다.

## 저장소 크기 기준

새 데이터셋 하나의 최초 검토 기준은 **16 MiB (16,777,216 바이트)**입니다.
압축 전 원본 응답, JSONL, 생성 행, 출처 기록, 수집 영수증, 완전 시리즈 선언을
포함하고 데이터셋 내 같은 경로는 한 번 셉니다. 코드·문서·Git 이력·압축은 제외합니다.
이는 저장소 유지보수 기준이며 수집기나 네트워크의 크기 제한은 아닙니다.
허용된 후보는 스테이징 전에 같은 파일별 크기·해시 목록을 기록해야 합니다.
완전 시리즈를 기준에 맞춰 잘라내지 않습니다. 기준을 넘는 데이터는
[서비스 계층 작업](https://github.com/WeaveTrail/WeaveTrail/issues/206)과 별도 허가 검토
전까지 검증 범위 밖에 둡니다.
[ADR 0054](adr/0054-record-blocked-data-admission-with-a-coverage-baseline.md)(영문)에 이유가 있습니다.

아래 기존 파일 크기는 이어지는 평가 명령의 캡처 결과입니다. 모두 검토 기준
안에 있으며, 반입이 막힌 후보 데이터의 크기 추정치가 아닙니다.

| 기존 데이터셋       | 보존 바이트 | 관측 행 / 제공자 전체 행 |

## 재현 가능한 범위 평가

```bash
pnpm eval:coverage
```

[평가 정의](../packages/evals/src/claim-coverage-cases.ts)는 작성된 구조화 요청 12개를
한 번씩 셉니다. 관측된 일별 범위 4개, 없는 종목·지수 3개(합성 식별자 1개 포함),
기간 밖 날짜 2개, 장중 요청 1개, 없는 필드 2개입니다. 사용자 메시지를 수집한 것이
아니며 시장 사실을 주장하지 않습니다. 정식 식별자를 직접 공급하므로 이름 해석과
붙여넣기 추출은 측정하지 않습니다. `expiryDate`와 `foreignNetVolume`은 미지원 필드
예시로서 실제 출처의 열이나 파생 행에 추가되지 않습니다.

기존 5개 데이터셋 ID로 고정한 기준 범위와 현재 매니페스트를 비교합니다.
공개 커버리지 API와 같이 숫자 계산 정의를 공급하지 않습니다.
[결과 원본](../packages/evals/results/published-claim-coverage-v1.json)은 두 매니페스트와
보존 파일의 해시·크기를 고정합니다. 명령은 기대값을 갱신하지 않고 일치를 확인하며,
원본 응답에서 모든 기존 데이터의 오프라인 재현도 검사합니다.

| 사전 확인 결과       | 이전  | 이후  |
| -------------------- | ----- | ----- |
| `UNCONFIRMABLE` 비율 | 12/12 | 12/12 |
| 지원 범위 밖         | 7     | 7     |
| 해상도 부족          | 1     | 1     |
| 계산 정의 미연결     | 4     | 4     |

`dist/coverage-evaluation/summary.json`과 `run.json`이 생성됩니다.
[기록된 실행 영수증](../packages/evals/results/published-claim-coverage-v1.run.json)은
정확한 명령·체크아웃 지문·환경(Node 22.18.0, pnpm 10.33.2, Vitest 5.0.1,
Linux x86_64)을 보존합니다. 단위 테스트는 데이터셋 누락과 관측 범위 변경을
거부하며 CI는 결과 검증과 영수증 생성을 실행합니다.

새 반입이 없어 **지원 범위 개선은 측정되지 않았습니다**. 이 비율은 구조화 요청의
커버리지 사전 확인 결과이며 실제 유통 메시지 실패율이나 문장 근거 등급 비율을
추정하지 않습니다. 관측된 일별 요청도 숫자 계산 정의가 없어 확인 불가입니다.
`READY`만으로 `COMPUTED` 또는 `DIFFERS`가 되지 않습니다. 숫자 재계산과
붙여넣기 확인은 계획 단계입니다. 향후 허가된 데이터 반입은 이 기록을 덮어쓰지
않고 같은 기준 범위와 비교하는 새 평가 버전으로 검토해야 합니다.
