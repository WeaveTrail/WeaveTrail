# AI 실패 기록

_[English](AI_FAILURE_LOG.md) · 영문 문서가 기준입니다._

관찰된 모델·검증기 실패, 그 실패가 깨뜨린 가정, 그리고 이에 대응한 변경을
기록합니다. 각 항목은 일회성 수정 메모가 아니라 공개 엔지니어링 이력입니다.
항목은 추가만 합니다. 이미 수정된 실패를 나중에 다시 바꾸면 이전 항목을
참조하는 새 항목을 씁니다.

실제로 관찰한 사례만 기록합니다. 커밋된
[`mapping-run/1` 기록](EVALUATION.ko.md)이 이미 담고
있는 범위를 넘는 원문 모델 출력은 인용하지 않습니다. 오프라인 프로브의 경우
반례는 커밋된 직접 작성 픽스처와 관찰된 검증기 결과입니다.

[`CONTRIBUTING.md`](../CONTRIBUTING.md#change-requirements)(영문)는 모델·검증기
실패를 고치는 변경이 이 기록의 항목과, 수정 없이는 실패하는 회귀 테스트를 함께
포함하도록 요구합니다. [기록 점검](../packages/evals/src/ai-failure-log.test.ts)은
`pnpm test`에서 실행되며, 항목이 불완전하거나 Git이 추적하지 않거나 테스트 스위트가
수집하지 않는 테스트 파일을 지목하면 실패합니다. 또한
[프롬프트 버전](#프롬프트-버전) 표가 프롬프트 버전 등록 목록과 다르면 실패합니다.

`F-001`부터 연속 번호를 붙인 각 `F-nnn` 항목은 다음을 밝힙니다.

| ----------- | ---------------------------------------------------------------------------------- |
| 역할        | 출력이 실패했거나 잘못 판정된 제한된 역할                                          |

| 실행 기록   | `mapping-run/1` 기록 참조, 또는 기록이 없는 이유                                   |
| 가정        | 프롬프트, 계약 또는 검증기가 전제한 것                                             |
| 반례        | 가정을 깨뜨린 형식(dialect)·프로필 ID와 관찰된 출력                                |

## 프롬프트 버전

이 표는 [`PROMPT_VERSIONS` 등록 목록](../packages/contracts/src/prompt-versions.ts)에
있는 버전을 빠짐없이, 그리고 그것만 나열합니다. 제공자 추적 정보의
`promptVersion` 타입이 이 목록이므로, 등록되지 않은 버전을 보고하는 제공자는
`pnpm typecheck`에서 실패합니다. scenarios의 사례 매니페스트 추적 정보도
`satisfies`로 목록과 대조합니다. 보조 점검으로, 기록 점검은 Git이 추적하는
테스트 외 소스에서 `promptVersion` 속성에 쓰이는 값과 `*PROMPT_VERSION` 선언을
해석해 등록되지 않았거나 문자열 리터럴 타입이 아니면 실패합니다. 소스가
작성하는 비모델 실행 기록도 프롬프트 없음 표시를 명시적으로 등록하며,
모델을 호출했다는 뜻은 아닙니다. 테스트에만
나오는 식별자는 모델에 전달되지 않으므로 등록하지 않습니다.
[ADR 0060](adr/0060-register-prompt-versions-for-the-failure-log.md)(영문)을
참고하세요.
보류(held-out) 세트가 만든 출력이 프롬프트, 계약, 검증기 또는 라우팅 변경에

검증기·후보·라우팅을 바꾸지 않았으며 프롬프트 버전도 그대로입니다. 결과를

[ADR 0069](adr/0069-recover-mapping-transport-with-a-fresh-held-out-set.md)(영문)의

`f869738c-fb61-42df-9b50-ecfd9c3b299a`에서 이제 사용되었습니다.
이후 프롬프트, 스키마, 어댑터, 검증기, 후보 또는 규칙을 바꾸면 또 다른 새
봉인 버전과 실행 전 ADR이 필요합니다.

v3의 완전한 격자에는 유효 출력 56개, 계약 거절 79개와 제공자 실패 45개가
있으며 자격을 갖춘 후보는 없습니다.
[복구 수집 기록](../packages/evals/results/mapping-held-out-v2/README.md)(영문)에
관측한 안전 경계 실패, 출력 누락과 변경하지 않은 규칙의 `NO_MODEL` 결정을
기록합니다. 이 결과에 맞춰 프롬프트나 임계값을 조정하지 않았습니다.

[ADR 0075](adr/0075-retry-mapping-selection-with-column-ids-and-a-fresh-corpus.md)(영문)는
무엇을 바꿀지 정하기 위해서만 이 기록의 실패 유형 네 가지를 분류하며, 임계값·정의·
동점 처리 규칙은 하나도 바꾸지 않습니다. 프롬프트·출력 스키마·어댑터·검증기는
새 `schema-dialects/4` DEV 분할에서 확인하며, `schema-dialects/4` HELD_OUT은
v4 모델 호출 전에 봉인했습니다. F-006과 F-007이 유형 1과 2를 기록합니다. 유형 3,
목록에 있었지만 HTTP 404를 반환한 후보는 `gemini-2.5-pro`를 후보에서 제외합니다.
유형 4, 시간 초과 9회는 마감 시간이 라이브 경로도 제한하므로 아무것도 바꾸지 않습니다.
2026-10-10 v4 DEV에서 ADR 0075 사전 게이트는 통과하지 못했습니다
([수집 기록](../packages/evals/results/mapping-dev-gate-v4/README.md)(영문)). 새 스택에서
후보 세 개의 null 정답 열에 만든 필드가 늘었습니다. ADR은 Proposed로 남고 보관 평가
집합 실행 전에 개정하며, v4 HELD_OUT은 아직 어떤 모델도 보지 않았습니다.
